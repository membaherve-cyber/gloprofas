# Internationalisation

Approach: per-locale columns on every content table (`title_en`, `title_fr`, `slug_en`,
`slug_fr`, `summary_en`, `summary_fr`, body arrays as JSONB) instead of a translation table.
Reasons: two fixed locales, short column list, simple queries, and index-friendly canonical
slugs. The admin view can render both languages side by side and mark the missing one.

Routing: `/[locale]/...` with middleware detection (Accept-Language) and a redirect from `/`.
UI copy lives in `src/messages/en.ts` (source of truth) and `src/messages/fr.ts`, typed as
`Dictionary` so missing French keys fail type-checking.

Slugs are locale-specific (e.g. `/en/scams/phishing` ↔ `/fr/scams/hameconnage`). Lookups fall
back to the other locale column when a swapped URL is requested, which keeps the language
switch on the equivalent content instead of a 404. `pick(locale, en, fr)` returns English when a
French value is empty, and metadata emits hreflang alternates for both locales plus x-default.
